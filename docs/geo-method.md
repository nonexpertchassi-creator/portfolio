# GEO 진단 방법론 — 1페이지

> 목표: 검색엔진과 답변엔진이 페이지의 주체·질문·답·근거를 혼동하지 않도록 만들고, 검증한 범위만 성과로 기록한다.

## 다섯 단계

| 단계 | 확인할 질문 | 산출물 | 통과 기준 |
|---|---|---|---|
| 1. Question | 이 페이지가 직접 답해야 할 대표 질문은 무엇인가? | 대표 질문 1개, 보조 질문 목록 | 페이지 목적을 한 문장으로 설명할 수 있음 |
| 2. Entity | 누가, 무엇을, 누구에게 제공하는가? | 정식 명칭, 운영 주체, 대상, 핵심 속성, 관련 entity | 대명사 없이도 주체와 관계가 남음 |
| 3. Evidence | 답을 제한하거나 증명하는 정보는 무엇인가? | 출처, 조건, 예외, 기준일, 공식 URL | 답과 근거가 같은 정보 단위 안에 있음 |
| 4. Structure | 사람과 기계가 같은 순서로 읽는가? | heading outline, 직접 답, meta·canonical, 내부 링크, JSON-LD | 화면의 내용과 메타데이터·스키마가 일치 |
| 5. Verify | 적용과 성과를 무엇으로 구분할 것인가? | 크롤링·스키마 검사, 대표 질문 기록, 전후 데이터 | 날짜·도구·대상 없는 성과 문장이 없음 |

## 문서 구조 원칙

    H1  페이지가 무엇인지
     ├─ H2  What — 정의와 대상
     ├─ H2  Why — 해결하는 문제와 차이
     ├─ H2  How — 이용 방법 또는 작동 방식
     ├─ H2  Conditions — 조건·예외·기준일
     └─ H2  FAQ
         ├─ H3  실제 질문 1
         └─ H3  실제 질문 2

- 질문 heading 다음 첫 문장에 직접 답을 둔다.
- 독립적으로 인용돼도 주체가 남도록 정식 브랜드·제품명을 필요한 위치에 쓴다.
- 홍보성 평가와 확인 가능한 사실을 같은 문장에 섞지 않는다.
- FAQ와 구조화 데이터에는 화면에 실제로 노출되는 질문·답만 넣는다.
- 바뀔 수 있는 정책·가격·수치에는 출처와 기준일을 연결한다.

## 업종별로 꺾이는 지점

| 공통 프레임 | 주류·FMCG | 금융·규제 산업 |
|---|---|---|
| 질문 → entity → 직접 답 → 근거 → 다음 행동 | 제품 정의와 브랜드 경험을 짧게 연결하고 FAQ로 남은 질문을 닫음 | 직접 답과 함께 조건·예외·고지·기준일이 반드시 남아야 함 |
| 인용 가능한 독립 문단 | 감성 카피 아래에 공식 답변 층을 추가 | 승인된 표현과 출처의 경계를 넘지 않음 |
| 구조화된 정보 | Product·Organization·FAQ 등 실제 화면에 맞는 타입 검토 | 상품 정보의 완전성과 면책·고지가 리치 표현보다 우선 |

## 구현 체크리스트

### 콘텐츠

- [ ] 대표 질문과 페이지 의도가 일치한다.
- [ ] 브랜드·제품·운영 주체·대상·핵심 속성을 명시했다.
- [ ] 각 section은 하나의 질문에 답한다.
- [ ] 첫 문장에 직접 답이 있고, 조건과 근거가 이어진다.
- [ ] FAQ가 실제 질문을 사용하며 추측 답변이 없다.

### 프론트엔드

- [ ] H1은 하나이고 H2–H3 계층을 건너뛰지 않는다.
- [ ] 핵심 콘텐츠와 링크가 렌더링된 HTML에 존재한다.
- [ ] title·description·canonical이 URL별로 고유하다.
- [ ] OG와 화면의 메시지가 일치한다.
- [ ] JSON-LD는 화면에 보이는 정보만 표현한다.
- [ ] 모바일·키보드·스크린리더에서도 정보 순서가 유지된다.

### 검증

- [ ] HTML·Schema 검사 결과와 날짜를 저장한다.
- [ ] 대표 질문, 사용 환경, 답변 결과를 같은 양식으로 기록한다.
- [ ] Before / After 비교는 같은 질문·모델·날짜 조건을 사용한다.
- [ ] Search Console 등 전후 데이터가 없으면 “적용”까지만 표기한다.

## 성과 표기 규칙

- **적용:** 코드·문서·배포 화면으로 확인된다.
- **검증:** 검사 도구, 대상, 날짜가 기록돼 있다.
- **변화:** 같은 조건의 전후 데이터가 있다.
- **성과:** 변화와 작업의 관계를 설명할 근거가 있다.
- **사례 후보:** 경험은 있으나 적용 범위나 결과 증빙이 부족하다.

“AI 검색 노출을 높였다”보다 “어떤 질문과 entity를 어떤 구조로 바꾸고, 무엇으로 확인했는가”를 먼저 적는다.
